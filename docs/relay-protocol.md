# 自动接力协议

让一个 Claude Code 会话当总调度，从第 1 步跑到第 12 步。Codex 的步骤由调度方用 `tools/run_codex_step.sh` 调用，用户不用在两个终端之间转达。步骤和分工见 [workflow.md](workflow.md)。

## 角色

- **调度方**：Claude Code 会话。自己完成主责步骤，到 Codex 的步骤就写好提示文件、发起调用，读完结果接着往下做。
- **Codex**：每一步都是一个新的 `codex exec` 会话，不记得上一步。连续性靠文件：每次调用都让它先读总日志、设计笔记和自己上一步的报告。
- **用户**：只在下面列出的暂停点介入。

## 运行目录

每次运行建一个目录 `Task/_notes/run-<日期>-<短名>/`：

| 文件 | 内容 | 谁写 |
|---|---|---|
| `RUNLOG.md` | 总日志，每步结束追加一行 | 调度方 |
| `steps/NN-<步骤名>-<agent>.md` | 每一步的报告 | 做这一步的一方 |
| `raw/` | 每次 Codex 调用的提示、事件流、最后回复和 `calls.tsv` | 脚本和调度方 |
| `decisions.md` | 两方分歧：各自的主张、裁决实验、结果 | 双方 |

`RUNLOG.md` 每行的格式：

```
| 时间 | 步骤 | 从 → 到 | 做了什么（一句话） | 结论或数字 | 产物路径 | 下一步 |
```

每一步的报告固定六节：

1. 收到的任务
2. 做了什么
3. 证据：数字、脚本、输出路径
4. 结论，以及它属于哪个证据等级
5. 未解决的问题和分歧
6. 交给下一方的具体问题

每步结束做一次 git commit，提交信息写成 `run <短名> step NN: <一句话>`。盲测期间提交标题保持中性，因为盲测进程可能看到最近的提交。

## 调用 Codex

1. 把提示写进 `<运行目录>/prompts/NN-<名>.md`，写明本步的问题、要读的文件、交付物位置。
2. 运行 `tools/run_codex_step.sh <运行目录> NN-<名>-codex <提示文件>`。可能要几十分钟，放在后台，等完成通知，不要轮询。
3. 读最后回复和报告，在 `RUNLOG.md` 记一行，再决定下一步。
4. 退出码不是 0 或报告缺失时，先读 `raw/*.err`，最多重试 1 次；还失败就记下并暂停问用户。

隔离调用（独立实现、对抗求解）：

- 先用 `tools/setup_probes.sh` 在仓库外建一个只含题面和数据的目录。
- 再把那个目录作为最后一个参数传给 `tools/run_codex_step.sh`。这时 Codex 是一个新的临时会话，只能在那个目录里写文件。
- 隔离提示里只能有题面原文和交付要求，不提参考解、结构、设计笔记或总日志。

## 暂停点

只有这些情况停下来问用户：

1. 需要用户本人的事实，而现有材料里没有。不得编造。
2. 设计循环（第 3 到 6 步）跑满 3 轮，原型盲测仍然没过。
3. 两方的分歧无法用实验裁决。
4. Codex 连续两次调用失败，或者工具和环境问题半小时内解决不了。
5. 第 11 步完成时：提交和对外行动只能由用户做。
6. 碰到用量上限，或者总运行时间超过 10 小时。不要反复重试，记下停在哪一步、从哪里恢复。

每次暂停都在 `RUNLOG.md` 写一行 `PAUSE`，说明原因和需要用户回答的问题。
