# 经验总结

下面是做一批基准任务后留下的通用结论。证据来自这一个项目的探针和关卡结果，样本不大，换了模型或评测方式可能不再成立。

## 强 agent 怎样解题

高 effort 的强 agent 通常会：

- 把数据说明里每一句类别事实当成清单，逐条去查。
- 按时间、分组、空间做表，自己画图再看图。
- 用误差变量回归、似然和信息准则比较、置换检验、bootstrap、多个随机种子。
- 在一切能观测的量上做整体验证。
- 外推时比较几种形式，用说明的措辞拍板，并写出假设错了会差多少。

所以，交代了的、看得见的、能在可观测量上验证的结构，它基本都会做对。

低 effort 的 agent 也不弱：说明里交代的机制、领域里最先会试的几个特征，它都会做对。它也会自己构造邻居特征、时间间隔特征和滞后特征。

## 什么能带来难度

挡不住强 agent 的：

- 同一行、同一天、同一时刻看得见的结构，叠多少层都没用。
- 每种都"几乎必被找到"的陷阱。加层只是增加工作量，不增加失手率。

还能带来难度的：

- 跨期的记忆效应，或组层面的滞后效应，而且历史里没有现成的反事实单位。
- 只影响外推部分、在可观测量上验证不了，但数据能识别的形式。
- 最优点落在历史范围外一点，又在权重最大的那一块。
- 两三种彼此独立、每种都有相当失手率的错法叠在一起。

## 公平性

- 每个影响评分的因果渠道，都要在材料里说明它可能存在。形式、滞后和大小可以不给。
- 说明里的安慰话（same kind of、do not change、independent、stable）要逐句对照生成器，必须字面成立。
- 题面写的阈值必须和验证器一致，不能有没写出来的容差。
- 读失败轨迹时，区分"判断失误"和"材料否认或从没给机会知道的事实"。后者是题目的问题。
- 修掉公平性问题后，之前的盲测结果作废，要重测。
- 每个评分输出都要挡住自然的零模型。只靠零模型就能通过的输出不要评分。

## 选题

开工第一天先过三关，再写代码：

1. **题材要新。** 领域里最经典、最常拿来做例子的题大概率撞车。
2. **评的是对系统的推断。** 运营方案和"从合成记录里还原埋进去的常数"都不够好，优先用真实数据。
3. **写下强 agent 会怎么做。** 把全部评分渠道按类别写进说明以后，难度还要站得住，否则换题。

换领域重做自己的旧题也算重复，表面改得再彻底也一样。

## 探针怎么用

- 第一版原型就用强 agent 隔离求解 2 次。30 分钟内大余量解出，就换题或换难度来源，不要一层层加。
- 求解次数会高估通过率，要同时看用时和余量：约 1 小时且贴关，和几分钟大余量，意义完全不同。
- 设止损：两轮加难后强 agent 仍然解出，就停下来重新考虑。
- 用真实的预测说话。预计通不过的，直接说不建议提交。

## 流程卫生

- 长任务放后台，只按自己进程树的 PID 发信号。按名字匹配可能误杀别的会话的进程。
- 盲测要等完成通知再计分。中间产物可能得出和最终结果相反的结论。
- 盲测期间提交标题保持中性。
- 开工前确认各 agent 的用量额度。额度用完时的报错可能混进结果。
- 真值评估一开始就做成查表，优化和扫描会快很多。
- 数据说明由生成器的参数生成，避免文字和数据对不上。
