# 工作流

原则：Codex 负责"这个题在数学上成不成立、会不会被聪明地绕过"，Claude Code 负责"把它做出来并证明它可靠"。每一步都有一个主责方，另一方做复核。

## 步骤与分工

| 步骤 | 主责 | 另一方 |
|---|---|---|
| 1 选题 | Codex 提出 3 到 5 个候选的数学结构，每个附上可识别性论证 | Claude Code 查重和筛选 |
| 2 pitch 四行 | Claude Code 按模板写 | Codex 挑刺：失败模式真的不一样吗 |
| 3 设计隐藏结构 | Codex 设计结构，并证明它在数据里能识别 | Claude Code 用探针的习惯攻击：回放、分组校准、残差、方差、尾部、滞后关联 |
| 3b 最短路线审查 | Codex 当红队：有没有一个通用的模型升级能一次绕过所有结构；有没有直接的前向检查或教科书式的路线 | Claude Code 把结论写进设计笔记 |
| 4 原型：生成器、真值评估、前沿 | Claude Code 写代码，真值评估做成查表 | Codex 审数学：真值有没有用到数据给不了的信息 |
| 4b 决策代价、打分口径 | Claude Code 跑扫描（每个结构单独漏、全漏、碰巧留余量） | Codex 判断代价是一阶还是二阶，必要时提出换口径 |
| 5 原型盲测 | Claude Code 用低 effort 子代理跑 3 次 | Codex 在隔离目录里以高 effort 解 1 到 2 次 |
| 6 读报告、反事实替换 | Codex 判断每个结构是被发现、被猜到还是被剔掉 | Claude Code 写替换脚本、出数字 |
| 7 建包、写题面和说明 | Claude Code | Codex 只核事实：每个数字能否追到证据，有没有泄露方法 |
| 8 一致性检查、30 种子校准 | Claude Code 写参考解、校准、消融阶梯 | Codex 只看题面和数据，独立写第二条路线的解法 |
| 9 本地运行、防作弊 | Claude Code | Codex 列出作弊写法，Claude Code 实现成测试 |
| 10 定稿盲测 | Claude Code 用低 effort 子代理跑 3 次 | Codex 在隔离目录里再解 1 次 |
| 11 提交材料 | Claude Code 起草，用户提交 | Codex 核对说明里的事实和数字 |
| 12 提交后复盘 | Claude Code 整理关卡结果 | Codex 读失败轨迹，判断原因 |

5、6 两步可以循环多轮。原型盲测里低 effort 子代理 3 次解出 2 次及以上，就改设计或换题，不进入第 7 步。

## 信息隔离

这是流程里最重要的一条。有三处必须真正独立，否则这一步就失去了意义：

1. 第 8 步的独立实现
2. 第 5、10 步 Codex 的对抗求解
3. 第 5、10 步的低 effort 盲测

做法：

- 用 `tools/setup_probes.sh` 建盲测目录，目录里只有题面和数据。目录放在仓库之外。
- 隔离任务在那个目录里新开会话，不读仓库里的任何文件。
- 交接消息里不写参考解的思路，也不请隔离中的一方"参考某文件"。
- 做完后只把交付物拷回来，同时记录模型、effort、用时、是否正常结束。
- 低 effort 盲测和 Codex 求解的结果分开记录，不合并计数。

沙箱通常只限制写、不限制读，所以"不读仓库"要靠提示约束。每次都在报告里注明这一点。

## 证据等级

"包能跑"、"评分公平"、"本地某配置解不出"、"通过了正式关卡"是四个不同的结论。写结论时注明关卡、模型、effort 和次数，不要混用。

## 分歧怎么处理

分歧写进 `decisions.md`，用实验来裁决，不靠某一方让步。两边意见不一致的地方，往往最值得做实验。

## 校准要求

- 30 个种子，参考解和独立实现都要通过。
- 每道关单独设在"两条正确路线的最差误差 × 1.5"这个下限，取不低于下限的最小值。
- 消融阶梯的每一级都要失败，并逐条确认它是那条错误路线最强的合理版本。
- 另一条合理的正确做法也要能通过。
- 说明里写出的每个数字，都从发布的数据重新算一遍。
